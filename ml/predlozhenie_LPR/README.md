# predlozhenie_LPR. Предложение под роль лица, принимающего решение

Модуль определяет, в каком виде подать готовое кредитное предложение конкретному лицу, принимающему решение. Решение о выдаче и условиях формирует модуль personal_predlozhenie.

## Задача

Одно и то же предложение принимается с разной вероятностью в зависимости от адресата и формата. Владелец обращает внимание на сумму, срок и скорость. Финансовый директор оценивает ставку, график платежей и влияние на долговую нагрузку. Главному бухгалтеру необходимы документы и порядок учёта. Управляющему важны цель финансирования и включение платежа в план. Задача модуля: выбрать формат, акценты, канал и время подачи под роль ЛПР.

Ручные правила задают только общие приоритеты, например краткий формат для владельца и расчёт для финансиста. Взаимодействие роли с параметрами сделки сложнее. Дорогое и нагруженное предложение финансисту целесообразно показывать расчётом, у владельца такой формат снижает отклик, при крупной сумме возрастает значимость документов. Поэтому используется модель склонности. Она оценивает вероятность принятия предложения в зависимости от роли, формата, параметров сделки и истории взаимодействий. Модель также служит основой для A/B-теста: оценки по всем форматам возвращаются в поле alternatives, что позволяет сравнивать выбранный вариант с фактически показанным и переобучать модель на реальных логах.

## Данные

Требуется история показов предложения формата F человеку роли R с исходом. В банке источником служат логи интернет-банка, CRM и рассылок. Данные отсутствуют, поэтому формируется синтетический набор lpr_data.py: около 12 000 строк, seed 42. Функция отклика учитывает:

- базовую склонность роли и формата из матрицы ROLE_FORMAT_PRIOR в roles.py; матрица открыта и используется как fallback при отсутствии модели;
- параметры сделки: ставка, срок, сумма к обороту, нагрузка после выдачи, платёж к обороту, организационная форма;
- историю взаимодействий: число предыдущих показов и частоту кликов;
- шум для нелинейности зависимости.

Целевой признак: факт принятия предложения. month_idx обеспечивает разделение по времени, как в скоринге.

## Обучение

Обучение выполняет функция lpr_model.train при запуске python train.py:

- CatBoost, разделение по времени 80 на 20 по месяцам, категориальные признаки: роль, формат, организационная форма;
- метрики AUC 0.69 и KS 0.30, сохраняются в artifacts/lpr_meta.json, доступны через GET /metrics в поле lpr. Уровень ниже кредитного скоринга, что ожидаемо для поведенческих данных;
- объяснимость: вклады SHAP для выбранного формата, результат возвращается в поле why.

При отсутствии модели lpr_offer ранжирует форматы по матрице приоров с контекстными поправками, согласованными с генератором, и возвращает generated_by = prior.

## Результат

POST /lpr возвращает карточку предложения под роль. Тот же результат доступен внутри POST /pipeline в поле lpr.

| Поле | Содержание |
|---|---|
| format_code и format_title | выбранный формат: короткая карточка, расчёт, документы, решение под задачу |
| headline и body | текст, собранный из параметров кредитного решения; новые значения модуль не вводит |
| emphasis | акценты карточки: ставка и переплата для финансиста, пакет документов для главного бухгалтера |
| channel и best_time | канал и время отправки: push утром или вечером владельцу, письмо с расчётом финансисту |
| p_accept и alternatives | вероятность принятия выбранного варианта и оценки всех четырёх форматов |
| why | объяснение выбора для сотрудника банка и проверяющего |

Одна заявка и одно кредитное решение при четырёх вызовах /lpr с разными ролями формируют четыре разные карточки. При запрете на кредиты предложение отсутствует, но модуль используется для информирования: баннер о самозапрете для владельца и формулировка для финансиста различаются по тексту.
