# personal_predlozhenie. Персональное предложение бизнесу

Модуль определяет, стоит ли выдавать кредит и на каких условиях. Он содержит скоринговую модель, движок правил и формирование персонального баннера. Формат подачи под конкретное лицо, принимающее решение, реализован в модуле predlozhenie_LPR.

## Задача

По заявке малого бизнеса модуль решает три задачи:

1. Оценка риска. Число связей между признаками не позволяет корректно оценить риск пороговыми правилами. Используется модель CatBoost, которая возвращает вероятность дефолта и риск-грейд A/B/C/D.
2. Формирование условий. Ставка складывается из ключевой ставки, надбавки за риск по грейду и надбавки за продукт. Сумма ограничена PTI-бюджетом, то есть допустимым ежемесячным платежом при текущей нагрузке. Результат принимает одно из трёх значений: одобрение, встречное предложение с уменьшенной суммой или увеличенным сроком, отказ с перечнем условий для улучшения.
3. Объяснение решения. Для каждой заявки формируются вклады SHAP с формулировками для сотрудника банка и клиента.

Порядок принятия решения, от наиболее жёсткого условия к наименее:

1. Запрет на кредиты: самозапрет, запрет банка или ограничение приставов. Выдача отклоняется до обращения к модели.
2. Проверка элигибилити по возрасту бизнеса. Бизнес моложе шести месяцев относится к холодному старту и получает отдельный отказ.
3. Грейд D по модели. Отказ с перечнем условий для улучшения.
4. Грейды A, B, C с учётом PTI-бюджета и лимитов продукта. Результат: одобрение, встречное предложение или отказ.

Запрет на кредиты не является признаком модели. Модель может ошибиться, а действующий запрет отменяет выдачу независимо от её оценки.

## Данные

Признаки соответствуют данным, доступным банку на входе конвейера:

- профиль компании: организационная форма, отрасль, возраст бизнеса, численность сотрудников;
- динамика денежных потоков: среднемесячный оборот, выручка, маржинальность, доля расходов, признак кассового разрыва;
- обязательства и кредитная история: активные кредиты, текущий ежемесячный платёж, оценка БКИ, просрочки 30 и 90 дней; на демонстрационном стенде БКИ заменена заглушкой;
- параметры заявки: сумма, срок, цель; производные признаки PTI и отношение кредита к обороту;
- анкета: возраст заявителя, наличие залога.

Реальные данные недоступны, поэтому используется генератор synthetic.py: 15 000 заявок, seed 42. Целевой признак рассчитывается скрытой риск-функцией от тех же признаков. Просрочки и нагрузка повышают вероятность дефолта, залог и зрелость бизнеса понижают. Это обеспечивает разделимость классов и корректность метрик AUC и KS. Схема признаков задана в MODEL_FEATURES в synthetic.py и повторяется в контракте API schemas.py.

## Обучение

Обучение выполняет функция scoring.train при запуске python train.py из каталога ml:

- разделение по времени по month_idx: 80 процентов месяцев в обучение, 20 процентов в тест; часть конца обучающего периода отведена под калибровку;
- CatBoostClassifier с функцией потерь Logloss, глубина 6, 600 итераций;
- изотоническая калибровка вероятностей отдельным слоем с возможностью отключения; границы грейдов заданы в config.py;
- метрики и распределение грейдов сохраняются в artifacts/scoring_meta.json; текущие значения AUC 0.774, KS 0.420, PSI 0.010, дефолтность тестовой выборки 14 процентов.

Объяснимость строится на get_feature_importance с типом ShapValues для каждой заявки. Возвращаются пять факторов с направлением влияния и готовой формулировкой, например «кредит 3.2 к месячному обороту, высокая доля». Внешняя библиотека shap не используется, вклады рассчитывает CatBoost.

При отсутствии модели грейд рассчитывается эвристикой rules.fallback_grade по БКИ, просрочкам, PTI и возрасту бизнеса. Сервис сохраняет работоспособность.

## Реальная модель на датасете Kaggle MSME

Для проверки методики на реальных данных использован открытый датасет Kaggle MSME Credit Data by 30S-CR: 1707 компаний, 87 реестровых признаков, базовая дефолтность 5.98 процента. Полный разбор находится в ml/kaggle_integration.md. Изменения в модуле:

- kaggle_data.py читает ml/data/msme_kaggle.xlsx и применяет рецепт подготовки из лучшего открытого решения. Enterprise_id исключён как утечка, крупные числовые признаки приведены к шкале log2, счётчики событий сохранены отдельными временными окнами, поскольку агрегация суммой снижала AUC с 0.80 до 0.73, категориальные признаки сохранены в исходном виде. Модуль также содержит human_label с русскими подписями признаков и demo_profiles с пятью реальными компаниями.
- real_scoring.py обучает CatBoost на этой матрице: AUC 0.797, KS 0.512, PSI 0.066. Средняя вероятность дефолта 0.050 при фактической дефолтности 0.061, калибровка не потребовалась. Изотоническая регрессия на 320 строках давала постоянное значение и была исключена. Границы грейдов рассчитаны по квантилям распределения вероятности дефолта. Объяснимость построена на вкладах SHAP. Артефакты начинаются с real_msme, версия модели l2-msme-real-2.0.
- resmlp_reference.py воспроизводит архитектуру ResMLP на PyTorch для сравнения метрик: точность accuracy 0.939, AUC 0.673, доля предсказанных дефолтов равна нулю.
- msme_offer.py преобразует профиль компании в кредитную заявку. Датасет не содержит оборотов и параметров заявки, поэтому используются документированные допущения: годовой оборот принят равным трём оплаченным капиталам, сумма заявки равна двум среднемесячным оборотам, кредитный грейд переводится в прокси оценки БКИ. Исполнительное производство за последний год включает тот же жёсткий запрет, что и в синтетических данных.

Добавлены два эндпоинта: POST /msme/score для скоринга профиля и POST /msme/offer для полной цепочки до карточки ЛПР. При отсутствии артефактов возвращается ошибка 503, остальной контракт не изменяется.

## Результат

- POST /score возвращает ScoreResponse: вероятность дефолта, грейд, флаг запрета is_banned, топ-факторы.
- POST /decision возвращает DecisionResponse: исход approve, counter или reject, блок CreditTerms с продуктом, суммой, сроком, ставкой, платежом и PTI после выдачи, причины решения и машинные коды отказов.
- POST /banner возвращает BannerResponse типа offer, info или educational: заголовок, тело, CTA, чипсы. Текст может обрабатываться open-weight LLM при включённом ML_LLM_ENABLED=true; при недоступности используется шаблон.
- POST /banner/html возвращает тот же баннер в вёрстке раздела специальных предложений личного кабинета. Состав полосы: один персональный баннер и два классических продуктовых. Модуль banner_html.py только форматирует и экранирует готовые тексты, новых чисел не появляется.

Пример для демонстрационного профиля с кассовым разрывом и встречным исходом: вероятность дефолта 0.033, грейд A, запрошенная сумма превышает PTI-бюджет, поэтому формируется встречное предложение: 200 000 рублей на 36 месяцев, платёж 7 494 рубля в месяц, PTI после выдачи 22 процента. Баннер содержит смягчённую формулировку и сильные стороны профиля.
